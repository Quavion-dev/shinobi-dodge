# Shinobi-Dodge
Scratch arcade game focused on programming fundamentals, debugging, and user testing.

Shinobi Dodge is an arcade-style game I built in Scratch while working through Harvard University's CS50 course. The goal is to dodge falling weapons, survive as long as possible, and beat your high score.

## What I Built

-Player movement with keyboard controls and screen boundaries

-Four independently falling weapons

-Randomized weapon positions and different falling speeds

-Collision detection and game-over system

-Current score and persistent high-score system

-Background music and game movement

-Custom My Block for high-score logic

## Programming Concepts

This project gave me hands-on practice with:

-Loops and continuous program execution

-Conditionals and logical comparisons

-Variables and game-state management

-Events and user input

-Randomization

-Functions / My Blocks

-Colliso detection

-Debugging and problem solving 

## Debugging & Iteration

A major part of the project was testing different
approaches and fixing unexpected behavior.

Some of the problems I encountered included:

-Weapons spawning in unintended areas

-Weapons skipping the exact position used for their reset condition

-Weapons appearing halfway down the screen when i wanted them to enter from the top

-Player movement not behaving the way i wanted

-Separating the current score from the high score

I solved these issues by changing the spawning logic, improving conditional checks, controlling player boundaries, restructuring weapon timing, and separating score variables.

## User testing

After completing the game, I had ##38 students and teachers at my school play Shinobi Dodge and provide feedback##.

I also encouraged players to share the game with others. Their feedback helped me identify issues and make additional gameplay improvements.

This gave me experience with a real development cycle:

##Build, Test, Feedback, Debug and Improve##

## What I Learned

This project taught me that programming is an iterative process. I learned how to break a project into individual systems, troubleshoot unexpected behavior, test different solutions, and improve a project based on real user feedback.

More importantly, I gained experience taking a project from an initial idea to a ##completed, playable project tested by real users##.
